# Trwały zapis zwykłego rynku — 19 września 2026

Kontynuacja istniejących napraw. Diler był już zabezpieczony w zmianach z 15 września; ta partia obejmuje zwykłe towary (`/market/buy`, `/market/sell`).

## Wykonane

- Portfel, ekwipunek, liczniki handlu, magazyn rynku i wynik operacji zatwierdzają się razem w SQLite. Błąd zapisu magazynu wycofuje również zmiany gracza.
- Klient korzysta z istniejącego mechanizmu trwałych identyfikatorów dla kupna i sprzedaży. To samo żądanie po utracie odpowiedzi lub restarcie otrzymuje zapisany wynik, bez powtórnego rozliczenia.
- Dokument `market-state` w `world_documents` przechowuje pełny stan rynku. Backend wczytuje go przy starcie; nowe transakcje pobierają aktualny dokument i sprawdzają jego rewizję podczas zapisu.
- Stan w pamięci i powiadomienia są publikowane po zatwierdzeniu. Odpowiedź transakcji zawiera wyceniony i zapisany stan rynku.
- Istniejący, autoryzowany endpoint resetu resetuje również zapis rynku. Nie wykonywano resetu danych użytkownika.

Przed tą zmianą zwykły rynek nie miał trwałego zapisu. Jeśli dokument jeszcze nie istnieje, pierwsza udana transakcja zapisuje bieżący stan; dalsze restarty odtwarzają ten dokument. Regeneracja podaży nadal uwzględnia upływ czasu według dotychczasowych zasad.

## Sprawdzenie

- 54/54 testy przechodzą. Dodano awarię SQL przy zapisie magazynu po zmianie konta: pieniądze, ekwipunek i zapasy pozostają niezmienione, potwierdzenie nie powstaje i publikacja nie następuje.
- Test rzeczywistego API sprawdza powtórzenie zakupu, zachowanie podaży po restarcie i ponowienie zakupu oraz sprzedaży po restarcie bez zmiany salda.
- Pełny `npm run smoke` przechodzi, w tym ponawianie chronionych operacji.
- `npm run check`: 109 plików JS/JSX bez błędów składni.
- Eksport web i Android/Hermes zakończony sukcesem; nie jest to test APK na urządzeniu.

Testy korzystały z odizolowanych baz. Zmian nie opublikowano i nie restartowano działającego serwera użytkownika. Aby używać nowej logiki backendu w uruchomionej grze, trzeba ponownie uruchomić proces API.

## Co pozostaje

Zapis transakcji chroni konflikt między zapisującymi procesami, ale odczyty rynku i automatyczne zmiany cen nadal korzystają z pamięci pojedynczego backendu. Nie deklarujemy pełnej synchronizacji wielu instancji. Pozostają testy obciążenia, kopii/odtworzenia i fizycznych telefonów oraz przegląd pozostałych płatnych akcji pod kątem powtarzania żądań. Następny etap rozgrywki to pomiar tempa progresji pierwszej godziny i tygodnia.
